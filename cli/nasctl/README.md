# nasctl

CLI для ограниченных операций с фильмами через Radarr API v3.
Radarr использует уже настроенные Prowlarr и qBittorrent. Постоянный
дополнительный сервис не требуется. Python 3.10+, только стандартная библиотека.

```text
nasctl find "Spider-Man Brand New Day"
nasctl add 969681
nasctl releases 969681
nasctl download 969681 <release_id>
nasctl download 969681 <release_id> --execute
nasctl status 969681
```

`add` регистрирует фильм без автоматического поиска и мониторинга.
`releases` показывает варианты, прошедшие политику конфигурации.
`download` повторно проверяет релиз, наличие файла, очередь и свободное место.
Без `--execute` это предварительный просмотр; с ним — отправка в Radarr.
`status` сообщает состояние Radarr, но не подтверждает доступность в Jellyfin.
Русская дорожка предварительно определяется по настроенному шаблону названия;
проверка фактических дорожек после скачивания ещё не реализована.

## Конфигурация и права

Ubuntu: `/etc/nasctl/`; macOS: `/Library/Application Support/nasctl/`.
Внутри находятся `config.json` и `secrets.json`. Путь фиксирован: агент не
может подставить другой конфиг, endpoint, каталог или API-ключ аргументами CLI.

`config.example.json` — пример, не готовая политика. Укажи реальный UID
отдельного пользователя, профиль Radarr, каталог и согласованные лимиты.
В `secrets.json` нужен только `radarr_api_key`. Логин и пароль qBittorrent
этому инструменту не нужны: его подключением управляет Radarr.
Реальные секреты хранятся вне репозитория и не выводятся инструментом.

Для защищённой установки администратор должен:

- Создать отдельного пользователя без административных прав.
- Установить проверенный код в каталог, который агент не может изменять.
  Код, конфиги и родительские каталоги принадлежат root и не доступны на запись
  группе или остальным пользователям.
- Разрешить чтение `secrets.json` только root и выделенной группе пользователя
  инструмента (например, права `0640`). Агент не входит в эту группу.
- Настроить запуск только установленного `nasctl` под этим пользователем.
  Не разрешать произвольный Python, shell, переменные окружения и произвольный
  путь скрипта. При sudo учитывать очистку окружения и Python-путей.
- Изолировать агента от секретов, браузерных сессий и прямого управления NAS.
  Не выдавать ему общий sudo или доступ к Docker.

Защиту обеспечивает эта установка вместе с проверками CLI. Запуск исходника
под обычным пользователем не создаёт границу безопасности. CLI откажется
работать с конфигами, не соответствующими проверяемым требованиям.
Проверки очереди не атомарны при параллельных запусках: для строгих лимитов
установка должна сериализовать операции записи, например через системную блокировку.

## Ограничения первой версии

Нет удаления, замены существующих фильмов, изменения настроек и произвольных
запросов API. Нет фонового наблюдения, проверки Jellyfin и хранения истории
заданий. Неизвестный итог сетевого запроса не приводит к автоматическому повтору.
CLI принимает только разрешённые Radarr релизы и использует непрозрачный ID
вместо произвольного URL. Не передаёт ключ на HTTP-перенаправления и не использует
прокси из окружения.

Проверено локально на имитации API. Защищённая установка и запуск на macOS
ещё не выполнялись; реальные загрузки этим CLI не запускались.

Документация API: https://radarr.video/docs/api/
