# NAS MCP

Удалённый MCP для ограниченного управления фильмами через Radarr API v3.
Работает на NAS в Docker. Использует официальный Python MCP SDK и Streamable
HTTP по `/mcp`. Radarr использует свои подключения к Prowlarr/qBittorrent;
их пароли серверу не нужны.

Инструменты: `find_movie`, `add_movie`, `find_releases`, `preview_download`,
`download_movie`, `get_status`. Сначала выбрать фильм, зарегистрировать,
получить релизы, показать предварительный результат и отправить выбранный релиз.
Нет удаления, произвольных URL, изменения настроек и автоматического поиска.

## Установка на NAS

Скопировать библиотеку на NAS, например в `/volume1/docker/skills`.
Контекст Docker — корень библиотеки: сборка включает `cli/nasctl/nasctl.py`.
Отдельно создать `/volume1/docker/nas-mcp-private`, вне библиотеки.
Поместить туда:

- `config.json`, подготовленный из `config.example.json`;
- `radarr_api_key`, только ключ Radarr без JSON;
- `mcp_token`, случайный токен не короче 32 символов.

Секреты вводить непосредственно на NAS; не отправлять их агенту.
Токен можно создать командой `openssl rand -hex 32` с перенаправлением в файл.
Каталог должен быть доступен только администратору; файлы контейнер читает
под UID 10001. Например, назначить файлам владельца `10001:10001` и права
`0400`; не менять владельца системных каталогов. Compose secrets здесь —
файловые монтирования, а не зашифрованное хранилище.

В конфиге указать действительный адрес Radarr, его профиль и путь к фильмам.
`http://radarr:7878` работает только в общей Docker-сети; для существующего
Radarr можно использовать его LAN-адрес. `allowed_hosts` должен содержать
имя/IP и порт, с которыми приходит клиент, например `192.168.1.47:8765`.
Все лимиты примера требуют выбора владельцем. Русская озвучка определяется
по названию релиза; фактические дорожки не проверяются.

В `mcp/nas/` скопировать `.env.example` в `.env` и задать реальный IP NAS
и абсолютный путь к приватному каталогу. Далее:

```sh
docker compose -f mcp/nas/compose.yaml up -d --build
docker compose -f mcp/nas/compose.yaml logs --tail=50
```

В Synology Container Manager можно создать проект с этим compose-файлом;
сохранить относительное расположение библиотеки и проверить поддержку
параметров Compose в установленной версии DSM. Запуск в DSM пока не проверен.

## Доступ и ограничения

Каждый HTTP-запрос требует `Authorization: Bearer <mcp_token>`.
Это заранее настроенный токен, без OAuth discovery или автоматического входа.
Клиент должен уметь передавать заголовок. Настройки харнесса находятся отдельно
в `harnesses/`; подключение конкретных клиентов пока не проверено.

Для удалённого доступа использовать HTTPS через reverse proxy или VPN.
HTTP в локальной сети не шифрует токен. Не открывать порт в интернет.
Настроить firewall NAS: разрешить MCP только нужным устройствам.
`allowed_origins` пуст по умолчанию; браузерный доступ не требуется.
Проверка Host включена; при reverse proxy добавить его точный Host в конфиг.

Контейнер не получает каталоги фильмов, Docker socket или SSH. Корневая
файловая система доступна только для чтения; процесс без root и capabilities.
Не выдавать агенту административный доступ к NAS или приватному каталогу.
Лимиты очереди сериализуются внутри одного процесса/контейнера; другие клиенты
Radarr могут одновременно менять очередь. Не запускать несколько реплик.

Ошибки записи не повторяются автоматически: после таймаута проверять статус.
`hasFile` означает файл в Radarr, не подтверждение Jellyfin. Текущая версия
не проверяет фактическую озвучку и не ведёт фоновое наблюдение.

## Проверки

```sh
uv run --with 'mcp==1.30.0' --with 'uvicorn==0.54.0' \
  env PYTHONPATH=mcp/nas/src:cli/nasctl \
  python -B -m unittest discover -s mcp/nas/tests -v
```

Автотесты проверяют авторизацию, разрешённый набор инструментов, скрытие
секретов, отказ от произвольного URL и последовательность операций.
Развёртывание на NAS и реальные загрузки через MCP ещё не проверены.

Документация SDK: https://github.com/modelcontextprotocol/python-sdk/tree/v1.x
